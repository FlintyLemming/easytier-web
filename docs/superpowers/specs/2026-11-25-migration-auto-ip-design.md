# 迁移向导：共用固定 IP 的设备改用自动选择的地址（短设计）

## 为什么

生产副本演练发现：组 A 的 38 台运行中的设备只有 15 个不同的固定 IP。中央网络里一个地址只能给一台设备（后端拒绝重复），所以现在的向导每个地址只能迁移一台，其余 27 台迁移不了。用户 2026-11-25 选择：在向导里加「改用自动选择的地址」。

## 目标 / 非目标

- 目标：一次运行就能迁移共用地址的设备；每台设备换到的新地址在执行前就能看到、逐条确认；新地址不和任何还在用旧配置的设备冲突。
- 非目标：不改中央网络或后端；不做地址的手动输入（要指定地址，迁移后在成员设置里改）。
- 反目标：静默地给设备换地址；新地址和迁移中、暂不迁移或离线的旧实例撞车。

## 方案

1. **向导选一个空闲地址并设成固定 IP**（采用）：取目标网段里最小的可用主机地址，避开这一组所有旧实例的固定 IP（运行或停用、迁移或不迁移）、目标网络已有成员的地址、以及本次已经替别的设备选走的地址。执行前在第 3 步显示，稳定、可预期。
2. 不设固定 IP，入网后由 easytier-web 分配（不采用）：后端只避开成员的地址，迁移期间还在跑旧配置的设备（同一个虚拟网络）可能被分到同一个地址；地址也要到执行后才知道。

用户对方案没有偏好，按 1 做（实现者的判断）。

## 行为

- **哪些设备可以改用**：选了「迁移」、固定 IP 有冲突的设备——和另一台选了迁移的设备重复（duplicateIp）、已被目标网络的成员占用（ipTaken）、不在网段内或是网络/广播地址（ipOutsideCidr）。
- **默认**：进入第 3 步时，duplicateIp 里按设备名排第一的那台保留原地址，其余改用自动选择；ipTaken 的全部改用自动选择；ipOutsideCidr 默认不改（多半是网段填错了，让用户自己决定）。用户可以在每台设备上切换「保留原地址 / 自动选择」；切回保留后冲突重新出现，「下一步」照旧不可用。
- **显示**：成员字段的固定 IP 一行显示「10.150.0.3 → 10.150.0.17（自动选择）」；第 3 类差异多一种「固定 IP：10.150.0.3 → 10.150.0.17」，要勾「我已了解」；摘要里「固定 IP · N 台」可以「全部确认」。
- **网段里没有空闲地址**：这台显示阻止项「网段 {cidr} 里没有空闲地址」，不能迁移。
- **执行**：执行器把第 3 步选好的地址当作这台的固定 IP（`PATCH virtual_ipv4`），不在执行时重新选；复查时这条差异必须已确认。后端仍然拒绝重复时照常回滚。
- **校验**：期望的 `virtual_ipv4` 用成员实际拿到的地址（记录里的成员字段），所以新地址也会被校验。
- **回滚**：恢复旧配置（原来的地址），和现在一样。

## 留给实现者

- 选址放在 `planGroup`（纯函数、按设备名顺序、可单元测试）；页面只保存每台设备「保留 / 自动」的选择。
- 文案原样用本文的中文；英文对应翻译。
