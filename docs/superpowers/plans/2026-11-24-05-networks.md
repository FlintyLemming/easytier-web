# 网络页 实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 做出「网络」页面：网络列表和新建网络；网络详情的成员、ACL、凭据（仅安全模式）、设置四个标签页。所有写操作有加载、成功、失败提示，危险操作二次确认，ACL 整体写回时不丢规则内容。

**Architecture:**
- **API 层：**`src/api/client.ts` 补上网络增删改查、gateway-info、ACL 策略、凭据和临时成员的接口。返回结构以 Task 1 从本地 testenv 抓到的 fixtures 为准。
- **纯函数：**`src/domain/networks.ts`（设置表单 ↔ 请求体、网段规范化、成员行、随机密钥、凭据接入信息）和 `src/domain/acl.ts`（选择器、规则草稿 ↔ 规则、端口解析、摘要文字），全部单元测试覆盖。
- **页面：**`NetworksPage`（列表 / 只有一个网络时跳转）、`NetworkDetailPage`（页头 + 四个标签页）。列表和成员数据读 inventory store（AppShell 已经每 5 秒轮询 `/networks` 和每个网络的 `/members`），网络详情、ACL、凭据由页面自己读取。
- **组件：**放在 `src/components/networks/` 下，每个标签页一个组件，对话框各自一个文件。

**Tech Stack:** 不新增依赖。沿用 Vue 3.5、Pinia、vue-router、vue-i18n、Tailwind v4、Reka UI、`uuid`，以及现有的 `UiButton`、`UiDialog`、`UiInput`、`UiMenu`、`UiBadge`、`SectionCard`、`EmptyState`、`SkeletonRows`、`CopyButton`、`KeyValueList`、`StatusDot`、`useConfirm`、`useToast`、`usePolling`、`useNarrow`、`ListField`、`listenerRule`。

**Spec:** `docs/superpowers/specs/2026-11-23-easytier-web-console-design.md`（§5.3 路由、§5.8 网络页、§5.9 视觉、§6.5 写操作、§6.9 webhook 降级）

**规划时核实的事实**（都在本地 testenv 上实测过：web v2.7.1，core 2.6.4；探测用的临时网络已删除，没有碰生产环境）：
- **新建：**`POST /networks {settings, network_secret?}`，`settings = {display_name, network_name, networking_method, public_server_url, peer_urls, virtual_cidr, secure_mode}`。返回 `NetworkDetail`（含 `network_secret`）。`network_name` 为 null 或空白时，后端生成 `<显示名 slug>-<8 位十六进制>`；`network_secret` 省略时后端生成 32 字节随机数的 base64；网段不带前缀时补 `/24`。自定义密钥在 v2.7.1 已经支持（main 只是给原版前端加了输入框）。
- **修改：**`PATCH /networks/{id} {settings, network_secret?}`，settings 必须完整。`network_name` 为 null 时**保留原网络名**；`network_secret` 省略时保留原密钥。**网段改变时，所有成员的自动分配 IP 会被清空并重新分配**（`service.rs update_network`）。
- **删除：**`DELETE /networks/{id}` 返回 204，有成员时也能删；成员设备上的实例在约 30 秒内被撤下。
- **组网方式：**`PublicServer` 需要 `public_server_url`；`Manual` 需要至少一个 `peer_urls`；`Standalone` 不需要地址；`Gateway` 只在 `GET /networks/gateway-info` 返回 `enabled: true` 时可用（否则 400 `Gateway runtime is disabled`），保存时只发 `networking_method: 'Gateway'`，地址由后端填。读回时 Gateway 网络的 `peer_urls` 是网关地址。
- **错误：**业务错误返回 `{message}`，状态码 400（校验）、404、409（冲突）。实测的 message：`display name must not be empty`、`manual networking requires at least one peer URL`、`invalid network URL: foo`、`invalid virtual subnet: 10.201.0.300/24`、`Gateway runtime is disabled`、网络名重复时 409 `…UNIQUE constraint failed: networks.user_id, networks.network_name`、成员重复时 409 `device already belongs to network: <id>`。请求体缺字段时是 **422 纯文本**（`Failed to deserialize the JSON body…`），现有 `request()` 会把文本当 message。
- **成员：**`POST /networks/{id}/members {device_ids, temporary, ttl_seconds?}` 返回 204，所有 id 先校验再一起写入。`temporary: true` 要求网络是安全模式（否则 400 `temporary members require secure mode`），`ttl_seconds` 范围 1 秒到 365 天，默认 7 天。临时成员在成员列表里 `temporary: true`、`credential_id: "member-<member_id>"`、`credential_expiry_unix` 有值；2.6.4 的 core 能以临时成员身份在安全模式网络里正常运行。
- **ACL：**`GET /networks/{id}/acl-policy` 返回 `{policy}`，从没设置过时是 `{default_action: 'allow', rules: []}`。`PUT` 的请求体就是策略对象本身（不是 `{policy}`），返回 `{policy}`。每条规则的字段 `id, name, enabled, action, sources, destinations, protocols` 全部必填（缺 `enabled` → 422）。后端校验（`compiler.rs validate_acl`）：id 不能重复也不能为空；name、sources、destinations、protocols 都不能为空；引用的成员必须存在；`group` 来源必须是某个凭据授予的组（否则 400 `ACL references an ACL group not present in any credential grant: <name>`）；`stateful` 只能用于 TCP；ICMP / ICMPv6 不能带端口；端口是 `1–65535` 的单个数字或 `起-止`（起 ≤ 止），否则 400 `invalid ACL rule <id>: invalid port 0`。端口列表为空表示所有端口。**规则顺序就是优先级**：启用的规则里越靠前优先级越高。策略一旦保存过就不能删除，只能改。v2.7.1 只有临时成员的凭据带组（`member:<member_id>`），手动生成的凭据不带组。
- **移出成员会改 ACL：**`remove_device` 会把引用这个成员的来源、目标从规则里删掉，删空的规则整条删除。
- **凭据：**`GET /networks/{id}/credentials` 返回 `{credentials: [{credential_id, credential_secret, expiry_unix, reusable, online_peers: TemporaryPeer[]}]}`，**临时成员自己的凭据 `member-<member_id>` 也在里面**，吊销它返回 409 `credential is used by a network member: …`。`POST …/credentials {ttl_seconds, reusable?, credential_id?}`：`reusable` 默认 true；`credential_id` 为空时后端生成 `credential-<uuid>`；重复 id → 409 `credential already exists: <id>`；`ttl_seconds` 为 0 → 400。非安全模式网络生成凭据 → 400 `credentials require secure mode`。`DELETE …/credentials/{id}` 返回 204。
- **Plan 4 留下的提示**（ACL 编辑器要保留省略的枚举值）针对的是节点级 `NetworkConfig.acl`（protobuf，手动实例里用 TOML 编辑），**不适用于**中央网络的 ACL 策略：后者是普通 serde JSON，每个字段都必填，读到的对象就是完整内容。

**规划时做的决定**（spec §7 交给实现者决定的部分）：
1. **导航：**顶部导航在「设备」后面加「网络」，跳转 `/networks`。webhook 模式下不显示；webhook 模式下打开 `/networks*` 时 `router.replace('/')`。
2. **只有一个网络时的入口：**`/networks` 在恰好一个网络、且 URL 没有 `?list=1` 时，`replace` 到这个网络的详情。网络详情的面包屑「网络」链接到 `/networks?list=1`，这样只有一个网络时也能回到列表、新建第二个网络。没有网络时显示空状态和「新建网络」。
3. **橙色主按钮：**列表页的「新建网络」和成员页的「添加成员」各是所在页面唯一的 primary 按钮（沿用计划 2「加入网络」、计划 4「新建实例」的做法）。凭据页的「生成凭据」、ACL 的「保存」、设置的「保存」、所有对话框里的提交按钮都用 secondary。
4. **新建网络对话框的默认值：**gateway 可用时组网方式默认 Gateway、安全模式默认开（同上游）；否则默认 Manual、安全模式默认关。网络名和密钥都可以留空，由后端生成；密钥旁边有「随机生成」按钮（浏览器里 `crypto.getRandomValues` 取 32 字节转 base64，和后端格式一致）。
5. **标签页状态放在 query 里**（`?tab=members|acl|credentials|settings`，默认 members），可以链接、可以后退。非安全模式网络的 `?tab=credentials` 显示成员页。四个面板访问过一次以后保持挂载（`v-show`），这样切换标签页时 ACL 草稿和设置表单不会丢。
6. **成员行的样式**沿用设备表：表头 caption、细线分行、整行可点击进入 `/devices/:deviceId/networks/:networkId`（路由名 `device-network`），窄屏（< 640px）变卡片。列为成员、内网 IP、版本、状态、⋯。
7. **ACL 是「先编辑、再保存」：**规则的增删改、排序、启用开关、默认动作都只改本地草稿，页面上方出现「有未保存的修改」和「保存」「放弃修改」。离开页面时如果草稿有改动，弹确认框。排序用每行的「上移 / 下移」按钮，不做拖拽。删除规则不需要确认（保存前可以放弃修改）；**保存时**如果默认动作是「拒绝」，并且没有任何启用的「允许」规则，弹 danger 确认框。
8. **ACL 不丢内容：**没被编辑过的规则原样写回（同一个对象）。编辑过的规则，如果来源（或目标）的选择集合和打开时相同，原样保留读到的 `sources`（或 `destinations`）数组；只有选择变了才重建。组来源只显示已经出现在规则里的组，不能新建组（v2.7.1 手动生成的凭据不带组）。`member:<id>` 形式的组如果对得上临时成员，显示成员名。
9. **ACL 的协议**编辑成一个列表，每行是协议（TCP / UDP / ICMP / ICMPv6 / 任意）、端口（逗号分隔，单个或 `起-止`，留空表示所有端口；ICMP 类没有端口框）、「有状态」（只有 TCP 有）。这样任何读到的协议组合都能原样表达。
10. **凭据页**每 5 秒刷新一次（只在凭据页可见时），用来更新在线节点。`member-<member_id>` 凭据标为「临时成员 {name}」，不提供吊销（菜单项不可用，提示「移出这个临时成员即可吊销」）。凭据密钥只在「接入信息」对话框里显示。
11. **接入信息**移植上游 `NetworkDetail.vue` 的 `credentialJoinCommand` / `credentialJoinToml`：节点地址取 PublicServer 的 `public_server_url`、Gateway 的 gateway-info `peer_url`、否则 `peer_urls[0]`。没有节点地址时，CLI 不带 `-p`，TOML 不写 `[[peer]]` 段（上游会写出 `uri = ""`）。
12. **设置页：**网络名可以改，但输入框下方提示「修改网络名会让所有成员重新连接」。保存时如果网络名、网段、组网方式或地址、安全模式中有任何一项改变，先弹确认框（非 danger）逐条列出影响；网段改变的那条写「所有自动分配的 IP 会重新分配」。请求体里网络名没改时发 `null`。
13. **网络密钥**在设置页显示为掩码，「显示」「复制」「重新生成…」。重新生成用最近一次读到的网络详情拼 settings（不带上设置表单里还没保存的修改），只改 `network_secret`，danger 确认。
14. **删除网络**放在设置页底部的危险区，danger 确认，正文写明成员数和不可恢复。删除成功后跳到 `/networks?list=1`。
15. **移出成员的确认文字**加一句「引用它的 ACL 规则也会被修改，只剩它的规则会被删除。」（只在这个网络有 ACL 规则时加）。

## Global Constraints

- 接口以 easytier-web **v2.7.1** 为准，返回结构以 `tests/fixtures/v2.7.1/` 为准，包括本计划 Task 1 新抓的那些。
- **ACL 整体写回：**`PUT acl-policy` 的请求体以读到的完整策略为基础，只改动用户编辑的部分（spec §6.5）。没被编辑的规则，写回时和读到的深度相等。
- **只发变化的部分：**修改网络时网络名没改就发 `null`、不重新生成密钥就不带 `network_secret`；成员相关修改仍走计划 2 的 `PATCH member`（本计划不新增成员字段编辑，入口在设备详情）。
- **危险操作要二次确认（danger）：**删除网络、重新生成密钥、移出成员、吊销凭据、保存「默认拒绝且没有启用的允许规则」的 ACL。
- **每个写操作**都有加载状态、成功 toast 和失败 toast（失败时显示后端返回的 message）。写操作进行中，相关按钮和对话框不可重复提交；对话框在请求进行中不能关闭（沿用计划 4 R13 的做法）。
- **数据刷新：**网络列表和成员读 inventory store；写操作成功后调用 `refreshInventoryFresh()`。网络详情（`GET /networks/{id}`）在进入页面时、保存设置后、重新生成密钥后读取。
- **webhook 模式**（`session.webhookMode`）：不显示「网络」导航，`/networks*` 跳回概览，不发任何 `/networks*` 请求。
- **不新增运行时依赖**，运行时不向第三方发请求。随机密钥用 `crypto.getRandomValues`。
- **视觉**：沿用计划 2 的 Global Constraints（token、无阴影、标题字重 400、网络名 / 网段 / IP / ID / URL / 密钥 / 端口用 JetBrains Mono）。橙色按钮见决定 3。状态色只用 success / error，离线用 muted-soft。
- **窄屏**（< 640px）：表格变卡片，页面 `scrollWidth <= 视口宽度`。
- **语言**：所有新文案同时加入 zh-CN 和 en，键名一致性测试必须通过。本计划给出的中文原样使用。
- **移植的代码**：从上游复制或改写的代码（凭据接入信息、网络名规则），文件开头加 `// Ported from EasyTier v2.7.1 (https://github.com/EasyTier/EasyTier), LGPL-3.0-or-later`。

## Review Focus

1. **ACL 往返不丢内容。**读到一条带两个 subnet 选择器、`any` 协议带端口、`stateful: false` 的 TCP 的规则，只切换另一条规则的启用开关后保存：这条规则在请求体里和读到的深度相等。测试放在 Task 2（单测）和 Task 5（e2e 检查请求体）。
2. **非法输入在发请求前拦下。**端口 `0`、`70000`、`90-80`、`abc`；ICMP 带端口；空名称；没有来源 / 目标 / 协议；网段 `10.0.0.300/24`；Manual 没有节点地址；PublicServer 地址格式不对。表单显示错误，提交按钮不可用。后端仍然拒绝时，原样显示 message。测试放在 Task 2（单测）、Task 3 和 Task 5（e2e）。
3. **只有一个网络、没有网络、网络被删。**一个网络时 `/networks` 直接进详情，面包屑能回到列表；没有网络时显示空状态；打开不存在的网络 id 显示「找不到这个网络」；在详情页删除网络后回到列表。测试放在 Task 3、Task 4 和 Task 7。
4. **写操作失败和重复提交。**新建网络、添加成员、生成凭据、保存设置、保存 ACL 返回 4xx/5xx 时：toast 显示后端 message，对话框保持打开、草稿保留；提交中按钮不可用。测试放在各自的 e2e。
5. **离开未保存的 ACL。**ACL 有改动时切换标签页草稿还在；离开页面时弹确认框，取消则留在原页。测试放在 Task 5。
